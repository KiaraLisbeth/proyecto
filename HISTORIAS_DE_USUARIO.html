Historias de Usuario - Sistema de Gestión Escolar

Módulo 1: Gestión de Sesión y Control de Accesos

HU-01: Login de Acceso Seguro

Como usuario registrado (Administrador o Docente)
Quiero iniciar sesión en el sistema usando mi usuario y contraseña
Para poder acceder a las funcionalidades correspondientes a mi rol de forma segura.

Criterios de Aceptación:

  • El sistema debe mostrar un formulario con los campos de usuario y contraseña.
  • Las contraseñas deben estar encriptadas usando bcrypt (Laravel Hash::make()) [RNF1.1].
  • Si las credenciales son incorrectas, el sistema debe mostrar un mensaje de error en línea sin recargar la página completa [RNF2.2].
  • El sistema debe denegar el acceso a un usuario marcado como "inactivo" [RF-01-4].

HU-02: Restricción de Acceso por Roles

Como administrador del sistema
Quiero que el sistema restrinja las vistas según los roles definidos (Administrador y Docente)
Para asegurar que cada usuario solo acceda a la información y opciones permitidas para su perfil.

Criterios de Aceptación:

  • Un Docente no debe poder acceder a las rutas de Administración (ej. gestión de docentes, años lectivos).
  • Si un usuario intenta acceder a una ruta no autorizada, el sistema debe redirigirlo a una página de error o al dashboard correspondiente.

HU-03: Cierre de Sesión e Invalidación

Como usuario logueado (Administrador o Docente)
Quiero poder cerrar sesión de forma segura
Para proteger mis datos cuando termino de usar el sistema.

Criterios de Aceptación:

  • Debe existir un botón o enlace visible para cerrar sesión.
  • Al cerrar sesión, la sesión activa en el servidor debe invalidarse [RF-01.3].
  • El sistema debe denegar el acceso continuo si el administrador marca al usuario como inactivo mientras tiene una sesión activa [RF-01-4].

Módulo 2: Gestión Académica (Rol Administrador)

HU-04: Gestión de Docentes

Como administrador
Quiero registrar, modificar y cambiar el estado (activo/inactivo) de los docentes
Para mantener actualizada la plantilla de personal sin perder su historial de archivos.

Criterios de Aceptación:

  • El administrador debe poder llenar un formulario para registrar un nuevo docente.
  • El administrador debe poder modificar los datos de un docente existente.
  • El sistema no debe permitir la eliminación física (borrado de base de datos) de los docentes, solo desactivarlos [RNF3.2].
  • El sistema debe mostrar un mensaje flash de éxito o error al realizar cualquiera de estas operaciones [RNF2.3].
  • La lista de docentes debe estar paginada (15-20 elementos por página) [RNF3.1].

HU-05: Gestión de Año Lectivo

Como administrador
Quiero poder activar un año lectivo
Para que las operaciones del sistema (subida de archivos, asignaciones) se registren en el periodo correcto.

Criterios de Aceptación:

  • El administrador debe poder seleccionar y activar un año lectivo.
  • Solo puede haber un (1) año lectivo activo a la vez [RF-02.2].

HU-06: Gestión de Carga Académica (Asignaciones)

Como administrador
Quiero asociar a cada docente los cursos, grados y secciones que le corresponden dictar
Para organizar la carga de trabajo y permitir que los docentes suban archivos en sus áreas correspondientes.

Criterios de Aceptación:

  • El sistema debe proporcionar una interfaz para seleccionar un docente y asignarle grado, sección y curso.
  • Las asignaciones deben reflejarse inmediatamente en el perfil del docente.

HU-07: Visualización del Dashboard General

Como administrador
Quiero visualizar un dashboard general
Para obtener una vista rápida del estado del sistema y accesos directos a las funciones principales.

Criterios de Aceptación:

  • El dashboard debe ser responsivo y amigable [RNF2.1].
  • Debe mostrar un resumen o atajos a la gestión de docentes, años lectivos y archivos.

Módulo 3: Gestión de Archivos y Evidencias (Rol Docente)

HU-08: Subida de Archivos y Evidencias

Como docente
Quiero subir archivos digitales asociados a mis asignaciones vigentes (grado, curso, bimestre)
Para mantener un registro de mis evidencias de trabajo durante el año escolar activo.

Criterios de Aceptación:

  • El docente debe poder seleccionar un archivo de su dispositivo.
  • Debe poder elegir el grado, curso (de entre sus asignaciones) y el bimestre correspondiente.
  • El sistema debe mostrar mensajes de error si falta algún campo o el archivo no es válido (validación en línea) [RNF2.2].
  • Al subir el archivo con éxito, se debe mostrar un mensaje flash [RNF2.3].

HU-09: Listado de Archivos Propios

Como docente
Quiero ver la lista de todos mis archivos cargados durante el año escolar activo
Para llevar un control de lo que he reportado en el sistema.

Criterios de Aceptación:

  • La lista debe mostrar solo los archivos pertenecientes al docente autenticado y del año activo.
  • La lista debe estar paginada (15-20 elementos por página) [RNF3.1].

HU-10: Previsualización de Archivos

Como docente
Quiero previsualizar mis documentos subidos en línea
Para verificar su contenido sin necesidad de descargarlos en mi dispositivo.

Criterios de Aceptación:

  • Debe existir un botón de previsualización junto a cada archivo en la lista.
  • La previsualización debe abrirse en el navegador.

HU-11: Papelera de Reciclaje

Como docente
Quiero poder enviar mis archivos a una Papelera de Reciclaje temporal y restaurarlos si es necesario
Para corregir errores de subida sin perder la información de forma permanente.

Criterios de Aceptación:

  • El docente puede mover un archivo a la papelera.
  • La lista de la papelera debe estar paginada [RNF3.1].
  • El docente puede visualizar los archivos en su papelera y elegir restaurarlos a su ubicación original.
  • Se debe mostrar un mensaje flash al mover o restaurar archivos [RNF2.3].

Módulo 4: Control y Auditoría de Archivos (Rol Administrador)

HU-12: Visualización y Búsqueda Global de Archivos

Como administrador
Quiero visualizar y buscar todos los archivos subidos por todos los docentes de la institución
Para realizar auditorías y controlar el cumplimiento de las entregas.

Criterios de Aceptación:

  • El administrador debe tener acceso a una vista con todos los archivos del sistema.
  • Debe poder usar filtros de búsqueda por: docente, año lectivo y bimestre.
  • Los resultados deben estar paginados (15-20 elementos) [RNF3.1].

HU-13: Descarga y Previsualización Global

Como administrador
Quiero descargar o previsualizar en el navegador cualquier archivo del sistema
Para revisar a detalle las evidencias subidas por los docentes.

Criterios de Aceptación:

  • El sistema debe permitir la previsualización directa en el navegador de cualquier archivo [RF-04-3].
  • Las URLs generadas para visores externos deben tener una vida máxima de 10 minutos (URLs firmadas temporales) [RNF1.2].

HU-14: Generación y Descarga de Reportes

Como administrador
Quiero generar reportes de cumplimiento filtrando por año lectivo y bimestre, y descargarlos (PDF, Word o Excel)
Para documentar y presentar el estado de entrega de evidencias de la institución.

Criterios de Aceptación:

  • El sistema debe permitir seleccionar el año lectivo y el bimestre para generar el reporte.
  • El reporte debe mostrar qué docentes han cumplido con sus entregas y cuáles no.
  • Deben existir opciones claras para exportar el reporte en formatos PDF, Word o Excel [RF-04.6].
